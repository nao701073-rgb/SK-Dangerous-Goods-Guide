# Part 209 データ品質管理要領

## 1. 目的
法令PDF、CSV、JSON等から危険物データを更新した際に、特別規定（SP）の二重登録や構造上の不整合を公開前に検出し、原典情報を失わずに正規化するための手順を定めます。

## 2. 今回の対応
既存の危険物データ2,725レコードを検査し、同一レコード内でSPが重複していた28レコードを修正しました。重複値だけを削除し、SPの初出順、国連番号、品名、分類、包装要件、備考、原典ページ・行番号は維持しています。

## 3. 更新後の検証
サーバーフォルダで次を実行します。

```powershell
npm run data:validate
```

正常時は次の状態になります。

- warnings: 0
- errors: 0

## 4. 重複を検出した場合
まず書換え前の確認を行います。

```powershell
node scripts/normalize-static-data.js
```

内容を確認後、次を実行します。

```powershell
npm run data:normalize
```

処理後、`docs/Part209_SP重複正規化レポート.json` に対象国連番号、原典ページ、修正前後のSP一覧が保存されます。

## 5. 公開前の確認
1. 正規化レポートの変更件数を確認する。
2. 該当レコードを原典PDFと照合する。
3. `npm run data:validate` を実行する。
4. 検索画面と詳細画面でSP表示を確認する。
5. 更新ファイル、検証結果、承認者を変更履歴へ記録する。

## 6. 留意事項
自動正規化は、同一レコード内に完全一致するSPコードが複数存在する場合だけを対象とします。異なるSPコード、条文本文、原典の重複記載を自動的に統合するものではありません。
