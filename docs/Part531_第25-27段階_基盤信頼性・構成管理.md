# Part 531 第25～第27段階：基盤信頼性・構成管理

## 目的
本番環境の性能・容量・バックアップ健全性、構成基準との差分、改善施策と承認を同一の証跡体系で管理します。

## 第25段階
- P95応答時間、エラー率、CPU、メモリ、DB接続、保存領域を記録
- バックアップ経過時間と復元試験経過日数を記録
- 測定証跡をSHA-256で固定
- 本番測定が24時間以上前、バックアップ24時間超、復元試験90日超を承認阻害要因として判定

## 第26段階
- 本番・ステージング・試験・開発の構成基準を版とSHA-256で管理
- 構成差分を重大度別期限で管理（重大1日、高7日、中30日、低90日）
- 責任者、是正実施者、結果検証者を分離
- パスワード、トークン、秘密鍵、メールアドレス等の実値を台帳へ保存しない

## 第27段階
- 健全性、容量、バックアップ、構成、セキュリティ、監査を起点に改善施策を登録
- 責任者と実施者、実施者と効果確認者を分離
- レビュー提出時の対象記録をスナップショット化してSHA-256で固定
- 作成・確認・承認の三者分離

## 本番導入
1. 完全バックアップを取得します。
2. `server/sql/114_part531_platform_reliability_configuration_governance.sql`を適用します。
3. システム設定から「基盤信頼性・構成管理」を開きます。
4. 実環境の監視結果、バックアップ・復元試験証跡、構成基準を登録します。
5. 異なる利用者で是正・検証・レビュー承認を実施します。
