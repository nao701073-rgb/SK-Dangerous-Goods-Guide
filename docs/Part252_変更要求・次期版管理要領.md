# Part 252 変更要求・次期版管理要領

## 1. 目的
機能追加、改善、不具合修正、法令・データ更新、セキュリティ、性能、廃止・置換、文書更新を、要求登録から影響評価、承認、試験、リリース候補化まで一貫して管理する。

## 2. 基本手順
1. 変更件名、対象機能、理由、優先度、希望適用日を登録する。
2. 業務、権限、法令、データ、性能、セキュリティ、文書への影響を評価する。
3. 誤表示、データ損失、権限逸脱、停止時間等のリスクと対策を記録する。
4. システム管理者が保留、承認、却下、緊急対応承認を判断する。
5. 承認済み要求についてテスト計画、結果、証跡を記録する。
6. 旧機能の維持、段階的廃止、ロールバック、データ互換性を確認する。
7. 条件を満たしたものだけをリリース候補として管理する。

## 3. 廃止・置換
機能を廃止または置換する場合は、利用状況だけを根拠にせず、法令、業務上の必要性、代替手段、保存データ、利用者周知、復旧可能性を確認する。本システムの利用は任意である。

## 4. 権限
本機能はシステム管理者専用とする。将来、安全環境室長へシステム管理者権限が正式移行された場合は、移行後の安全環境室長が管理する。

## 5. 証跡
変更要求、評価、承認、試験、候補判定、廃止・置換判断は監査証跡として保存する。秘密情報やパスワードは記録しない。
