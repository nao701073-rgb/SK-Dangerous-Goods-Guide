# Part 503 導入・運用仕様

## 1. 対応範囲

Part 503では、次の5項目を追加しました。

1. 申請書・写真・添付資料の中央保存と自動バックアップ
2. API・データベース側での権限制御
3. 法令内容の作成・原典照合・承認・公開の分離
4. 申請情報と添付資料の訂正・取消・復元履歴
5. 法令・コードマスターの分割読込とキャッシュ最適化

## 2. 重要：静的公開だけでは有効にならない機能

GitHub PagesやローカルHTMLだけで利用する場合、中央保存、サーバー側権限制御、共有監査履歴、自動バックアップ、人による承認ワークフローは動作しません。これらを正式運用するには、同梱の `server/` を社内サーバーへ配置し、PostgreSQLと永続ストレージを接続してください。

静的版では、危険物検索・法令参照等の閲覧機能とブラウザ内保存は引き続き利用できます。ただし、ブラウザ内保存は端末固有であり、中央バックアップの対象にはなりません。

## 3. 中央保存

### 保存対象

- 申請番号・申請内容
- 申請書・添付資料と版履歴
- 現場写真
- 固縛力参考算出の登録結果
- 訂正前後の情報、訂正理由、訂正者、訂正日時
- 法令原典、構造化データ、変更セット、照合・承認履歴

### 保存方式

- `STORAGE_PROVIDER=filesystem`：社内サーバーの永続ボリューム
- `STORAGE_PROVIDER=s3`：S3互換オブジェクトストレージ

ファイルは保存キー、SHA-256、容量、MIMEタイプと一緒にデータベースで管理します。取得時にもSHA-256を照合します。

## 4. バックアップ

`backup-scheduler` が設定間隔で次を保存します。

- PostgreSQLデータベース
- 添付ファイル一式、またはオブジェクトストレージ参照情報
- SHA-256一覧
- バックアップマニフェスト
- 実行結果・遠隔保管先・復元試験結果

遠隔保管を行う場合は `OFFSITE_BACKUP_COMMAND` を設定してください。バックアップ作成だけでなく、`server/scripts/verify-backup.sh` によりハッシュ、圧縮ファイル、添付アーカイブを検証してください。管理画面には復元試験の実施結果を記録します。

## 5. サーバー側権限制御

画面の非表示だけに依存せず、APIで毎回ログイン情報、役割、事業所範囲を検証します。

- ゲスト：申請・写真・添付資料へアクセス不可
- 事業所利用者：所属事業所の閲覧・登録
- 事業所管理者：所属事業所の管理
- 安全環境室職員：全事業所の閲覧、法令照合
- 安全環境室長：全事業所の管理、法令承認
- システム管理者：法令公開、バックアップ設定等

URLを直接指定した場合もAPI側で拒否します。

## 6. 法令の人による承認

`法令原典照合・承認管理` 画面で次の順に処理します。

1. 原典PDFを登録し、版、施行日、SHA-256を保存
2. 構造化データを登録
3. 変更セットを作成
4. 作成者以外が条文・別表・数値・ページを原典照合
5. 作成者・照合者以外が承認
6. システム管理者が承認済み版を公開

作成・照合・承認を同一人物が実施することは、API側で拒否します。

## 7. 訂正履歴

申請情報の更新・取消しは、元データを消去せず、次を履歴として保存します。

- 版番号
- 操作種別
- 訂正理由
- 訂正前・訂正後
- 変更項目
- 操作者
- 操作日時

申請番号管理画面の「中央訂正履歴を表示」から確認できます。添付資料も新しい版として追加し、取消し・復元を履歴化します。

## 8. 読み込み速度

従来約2.7MBだった法令・コード共通マスターを、メタ情報とコード情報へ分割しました。危険物詳細・コード参照画面は必要なファイルだけを読み込み、危険物ごとの判定基準は既存の判定リゾルバーを利用します。Webサーバーではgzipと長期キャッシュを使用します。
