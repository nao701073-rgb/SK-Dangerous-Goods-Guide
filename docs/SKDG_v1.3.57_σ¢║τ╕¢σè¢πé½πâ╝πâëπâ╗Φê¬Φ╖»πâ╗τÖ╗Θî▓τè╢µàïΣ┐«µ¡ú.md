# SKDG v1.3.57 固縛力カード・航路・登録状態修正

## 1. ①〜⑥カード表示
- ③「輸送条件と貨物を確認」を基準に、番号丸、見出しフォント、薄青見出し帯、罫線、角丸、本文余白を共通化。
- ①「申請書・航路から入力する」と②「写真を撮影・アップロードする」は、外側DOMから別々の独立カードとして構成。
- ①・②は見出し直下に専用本文ラッパーを設け、①上部に見えていた空白帯・二重枠の原因を除去。
- ③〜⑥は `quickEntryPanel` を外枠ではなくデッキとして扱い、各カード間に一定の余白を設定。
- ④は後から生成される `v1ContactStep` を共通カードへ正規化し、③〜⑥が欠落しないよう初期化を補強。
- PC・スマホとも、ラベル、入力欄、補足文の上下間隔を広げ、文字と枠が接近しすぎないよう調整。

## 2. Excel申請書からの航路入力補完
実際の確認ファイル `SKShinsei_z1785551414000.xls` では、次の項目を確認した。
- `船積地` → `横浜`
- `陸揚地` → `SHANGHAI`
- `発航予定年月日` → Excel日付シリアル `46227`（7月）

従来の取込処理は `船積港` / `陸揚港` を中心に認識していたため、この様式の `船積地` / `陸揚地` を取得できなかった。v1.3.57では表記揺れを追加し、発航予定年月日から想定出港月も抽出する。

取込後は次の順に連携する。
1. 船積港・陸揚港・想定出港月へ反映
2. 既存の「航路を推定して反映」処理を起動
3. 推定海域を `quickTransport`（簡易入力）へ反映
4. 同じ海域を `transportPreset`（詳細設定・計算条件）へ反映
5. `applyTransportPreset()` を通して固縛力計算の輸送条件係数へ連携

## 3. 登録状態の誤表示修正
- 「登録が完了しました」は、実際の `sk:ctu-registered` イベントが発生した場合だけ表示する。
- ページ初期表示、算出だけの実行、Excel/写真/AI反映、条件変更では登録完了を表示しない。
- 旧スクリプトが後から生成する「登録が完了しました」「基本条件は入力済み」等の重複緑表示を抑止。
- 条件変更・再算出時は既存の登録成功表示を解除する。
