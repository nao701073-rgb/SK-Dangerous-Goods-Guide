# Part 528　第19～第21段階 統合仕様

## 1. 対象

- 第19段階：監視ダッシュボード、通知エスカレーション、運用当番管理
- 第20段階：SLA／SLO、エラーバジェット、サービス水準管理
- 第21段階：容量予測、週次・月次・四半期運用報告、三者承認

## 2. 第19段階

当番表と当番期間をDBで管理する。主担当者と副担当者は同一人物にできない。当番引継ぎは当番者本人が確認する。アラートは重大・高・中・低の4段階とし、重要度別の応答期限・復旧期限を設定する。

未応答または復旧期限超過時はエスカレーション対象とする。エスカレーション手順は経過分数の昇順で登録し、対象役割または対象利用者を必須とする。重大・高アラートは、確認者と復旧完了記録者を分離する。

## 3. 第20段階

可用性、成功率、応答時間達成率、通知到達率、復旧達成率をSLOとして登録する。測定値は成功数／総数から算出し、目標値との比較、エラーバジェット残量を保存する。対象期間・証跡説明・SHA-256を必須とする。

重要SLOが未達の場合、運用報告の最終承認を遮断する。

## 4. 第21段階

DB、保存領域、API、通知、利用者数、同時セッションを容量管理対象とする。現在値、警告値、重大値、予測値、予測到達日、対策期限、責任者、対策計画を保存する。期限超過の未完了対策がある場合、運用報告を承認できない。

運用報告は週次・月次・四半期で作成する。作成者が提出し、別利用者が確認し、さらに別利用者が承認する。承認直前に未解決重大アラート、復旧期限超過、重要SLO未達、期限超過容量対策を再計算する。

## 5. 証跡と機密情報

提出時の運用状態をJSONスナップショット化し、SHA-256で固定する。承認時に同じハッシュを再計算し、不一致の場合は差戻しとする。画面・APIへパスワード、トークン、メール本文などの秘密情報を保存しない。

## 6. 権限

安全環境室長・安全環境室職員・システム管理者はダッシュボードを閲覧できる。登録、更新、確認、承認はシステム管理者に限定する。承認者分離は利用者IDで判定する。

## 7. 本番導入

1. `server/sql/111_part528_operations_command_center.sql`を適用する。
2. 当番表・エスカレーション方針・SLO目標を登録する。
3. 実アカウントで当番引継ぎ、重大アラート、SLO未達、容量期限超過、三者承認を確認する。
4. 監視システムからの自動アラート連携は、認証済み内部APIまたは管理者操作を介して実装する。
