# Part 219 役割別アクセス制御・監査要領

## 1. 目的
利用者50名程度の試験運用から将来150名程度へ拡張する際に、画面側とAPI側の権限差異を防止します。

## 2. 確定した役割
- ゲスト：危険物検索、関連法令、関連資料、ユーザー設定。申請番号・写真・履歴・お気に入り・システム設定は利用不可。
- 事業所利用者：所属事業所の申請番号・写真を閲覧、登録、編集、削除。
- 事業所管理者：所属事業所の運用管理と利用者管理。
- 安全環境室長：全事業所の申請番号・写真を閲覧、登録、編集。削除不可。限定システム設定を閲覧可能。
- 安全環境室職員：全事業所の申請番号・写真を閲覧。登録、編集、削除不可。
- システム管理者：全事業所の管理、削除、利用者・法令・監査・運用管理。

## 3. 自動監査
サーバーフォルダで次を実行します。

```powershell
npm run permissions:audit
```

結果は `docs/Part219_役割別権限監査レポート.json` に保存されます。

## 4. 受入確認
1. 各役割でログインする。
2. ホーム画面のメニュー表示を確認する。
3. URLを直接入力した場合のアクセス拒否を確認する。
4. 申請番号と写真について、閲覧・登録・編集・削除を試験する。
5. 特に安全環境室長の削除が画面とAPIの両方で拒否されることを確認する。
6. ゲストが申請番号・写真へアクセスできないことを確認する。
7. 監査ログに管理操作が記録されることを確認する。
