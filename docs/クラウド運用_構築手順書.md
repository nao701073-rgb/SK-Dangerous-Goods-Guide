# クラウド運用 構築手順書（Part 192）

## 1. 方針
本構成では、社内サーバーを設置しません。画面、認証API、PostgreSQL、写真保存をクラウド上に配置します。利用者約50名で試験運用を開始し、将来約150名まで同一構成を段階的に拡張します。

## 2. 推奨構成
- 画面: 静的WebホスティングまたはAPIと同一コンテナ
- 認証・業務API: Node.jsコンテナ対応クラウド
- データベース: マネージドPostgreSQL
- 写真: 初期はクラウドの永続ディスク、将来はオブジェクトストレージへの移行を検討
- メール: 外部メール配信サービスまたは利用可能なSMTP
- ドメイン: 専用サブドメイン
- HTTPS: クラウド側の自動証明書を使用

## 3. 初期規模
### 約50名
- API: 1 CPU、メモリ1GB程度から開始
- PostgreSQL: 共有または小規模プラン、10GB以上
- 写真保存: 10GB以上
- 日次バックアップ

### 約150名
- API: 2 CPU、メモリ2GB程度を目安に増強
- 必要に応じてAPIを2インスタンス化
- PostgreSQLの接続数、ストレージ、バックアップ保持期間を増強
- 写真容量の実績に応じて保存領域を拡張

上記は初期目安です。実際の同時利用者数、写真枚数、検索頻度を運用監視で確認して調整します。

## 4. 構築手順
1. クラウド上でマネージドPostgreSQLを作成します。
2. Node.jsのDockerコンテナを実行できるWebサービスを作成します。
3. `server`フォルダをビルド対象に指定します。
4. `.env.cloud.example`を参考に、環境変数をクラウドのSecret機能へ登録します。
5. 写真保存用の永続ディスクを`/var/data`へ割り当てます。
6. 初回デプロイ後、マイグレーションを実行します。
7. 初期管理者を登録します。
8. `/api/health`が正常であることを確認します。
9. 画面側のAPI接続先をクラウドAPIのURLへ設定します。
10. 利用者CSVをdry-runで検証後、一括登録します。

## 5. 初期コマンド
```bash
npm run migrate
npm run seed
npm run users:import -- /app/data/users.csv --dry-run
npm run users:import -- /app/data/users.csv
```

実行方法は利用するクラウドの管理画面、ジョブ機能または一時シェルに合わせます。

## 6. 安全環境室
- 安全環境室長: 1名
- 安全環境室 職員: 5名
- 全事業所の申請番号および関連写真を閲覧可能
- 初期設定では閲覧専用
- 氏名決定後、利用者CSVへ追加

## 7. 公開前確認
- HTTPSが有効
-秘密情報がソースコードやGitHubへ含まれていない
- データベースが外部へ直接公開されていない
- CORSが本番画面のURLだけに限定されている
- 初期パスワード変更が完了
- 管理者権限の人数が必要最小限
- バックアップと復元手順を確認
- 50名分の一括登録結果を確認
- 安全環境室の全事業所閲覧と編集不可を確認

## 8. GitHub Pagesについて
GitHub Pagesは画面の静的配信に利用できますが、認証APIやPostgreSQLは実行できません。利用する場合は、画面のみGitHub Pages、APIとデータベースはクラウドへ配置します。組織内情報を扱うため、公開範囲とアクセス制御を十分に確認してください。
