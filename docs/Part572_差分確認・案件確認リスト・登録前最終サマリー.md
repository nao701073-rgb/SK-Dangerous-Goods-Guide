# Part 572 差分確認・案件確認リスト・登録前最終サマリー

## 1. 申請書確認：今回の差分
既存案件を `applicationId` 付きで申請書確認画面へ開いた場合、Part 571の前回確認記録に加えて、前回登録内容と現在入力中の内容を比較します。

表示対象は、主要な案件基本情報と危険物明細です。危険物明細は国連番号を優先して前回行と対応付け、主要フィールドについて「変更」「追加」「未取込」「一致」を表示します。「最初の差分へ」から対象入力欄・明細へ移動できます。

この差分は確認補助です。前回の確認済み状態、確認理由、判定結果を現在の申請へ自動反映しません。現在の申請書原本と現在の自動判定・人確認を優先します。

## 2. 申請番号管理：案件確認リスト
選択中の案件について、次の情報をコンパクトに一覧表示します。

- 申請書確認記録
- 船名
- コンテナ番号
- 検査予定日／実施日
- 簡易メモ
- MSL取付点確認状況

「未入力」は案件によって不要な場合もあるため、原則としてエラー扱いしません。申請書確認やMSL未確認など、既存の確認記録上明確なものだけ注意表示します。

## 3. 固縛力参考算出：登録前最終サマリー
既存の「計算前チェック」と「登録前の確認」を変更せず、申請番号管理への登録欄の直前に最終サマリーを追加します。

最終サマリーでは、次を確認できます。

- この画面で算出結果を確認したか
- 最後の算出後に主要入力条件が変更されていないか
- 登録前確認が完了しているか
- MSL取付点に未確認表示が残っていないか
- 申請案件が連携されているか
- 現在の登録先

算出後に貨物質量、固縛材本数、MSL、支保力等を変更した場合は「再算出推奨」と表示します。ただし既存の算出ボタン・登録ボタンを遮断または置換しません。

## 4. 安全側の扱い
- 固縛力の「不足」は算出エラーではなく、必要抵抗力に対して現在の固縛力が不足するという有効な計算結果として扱います。
- 写真や刻印から得たMSL候補を自動確定しません。
- 確認済み取付点台帳の最小MSLを優先する既存表示補助を維持します。
- 引張系と支保・当て材の寄与は別々に扱う既存方式を維持します。
- DBスキーマ・保存形式の変更はありません。
