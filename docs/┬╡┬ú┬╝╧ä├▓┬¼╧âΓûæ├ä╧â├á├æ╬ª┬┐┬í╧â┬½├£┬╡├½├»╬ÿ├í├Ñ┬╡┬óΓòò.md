# 本番導入設定手順書

## 1. 前提
本システムは、Nginx、Node.js API、PostgreSQL、写真保存領域で構成します。機密情報はHTMLやJavaScriptへ直接記載せず、サーバー側の環境変数と証明書ファイルで管理します。

## 2. 社内DNS
1. 社内DNSへ `inspection.<社内ドメイン>` のAまたはCNAMEレコードを登録します。
2. 対象は社内サーバーまたはロードバランサーのアドレスです。
3. 利用端末から名前解決と443番ポートへの到達を確認します。

## 3. TLS証明書
1. 社内CAまたは正式なサーバー証明書を発行します。
2. `server/nginx/certs/server.crt` と `server.key` に配置します。
3. 秘密鍵のアクセス権をサーバー管理者のみに制限します。
4. `scripts/tls-expiry-check.sh` を定期実行し、期限30日前を目安に更新します。

## 4. 環境変数
`.env.example` を `.env` にコピーし、少なくとも次を変更します。
- DATABASE_URL
- POSTGRES_PASSWORD
- JWT_SECRET
- CORS_ORIGINS
- BOOTSTRAP_ADMIN_EMAIL
- BOOTSTRAP_ADMIN_PASSWORD
- 写真上限値
- 監査ログ保存日数

JWT_SECRETは十分に長いランダム値を使用します。パスワードや秘密鍵をGitへ登録しないでください。

## 5. 初期起動
1. `docker compose up -d --build`
2. `docker compose exec api npm run migrate`
3. `docker compose exec api npm run seed`
4. `https://<社内DNS名>/api/health` を確認
5. 初期管理者でログインし、直ちにパスワード変更

## 6. 認証
初期検証はローカル認証を使用できます。本番ではOIDC/Entra ID等の社内認証基盤へ移行し、検証後に `ALLOW_LOCAL_AUTH=false` とします。安全環境室管理者、事業所管理者、事業所利用者の権限を分離します。

## 7. バックアップ
データベースと写真を同じ時点で取得し、別媒体または別サーバーへ保管します。少なくとも月1回は復元試験を実施してください。

## 8. 本番判定
- DNS、HTTPS、証明書期限監視
- ログイン失敗時のロック
- 事業所権限制御
- 安全環境室の横断閲覧
- 写真上限のサーバー側強制
- 同期競合の検出
- バックアップと復元
- 監査ログの記録と保存期間
