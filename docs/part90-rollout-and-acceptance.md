# Part 90 段階導入・受入判定

## 1. 段階導入

1. 安全環境室の検証環境で、中央DB・写真保存先・認証・HTTPS・バックアップを確認する。
2. 第一ブロック4事業所から各1～2名を選定し、申請番号・写真・検索・関連資料AI要約を試用する。
3. 1週間の並行運用後、同期待ち・競合・写真容量・監査ログを確認する。
4. 要改善項目を解消し、バックアップ復元試験に合格してから対象利用者を拡大する。
5. 他ブロックは組織マスタとサーバー事業所マスタへ追加し、同じ受入試験を実施する。

## 2. 必須受入条件

- 安全環境室が全事業所の申請番号・写真を閲覧できる。
- 事業所利用者が他事業所データを閲覧できない。
- 申請番号の登録・編集・削除がオンライン同期される。
- 写真の登録・コメント編集・代表写真設定・削除が同期される。
- 写真枚数・1枚容量・事業所総容量の上限がブラウザ側とサーバー側の両方で働く。
- 通信切断中の更新が同期キューへ入り、復旧後に送信できる。
- 同時更新時に競合を検出し、後勝ちで上書きしない。
- 監査ログに利用者・操作・対象・時刻が記録される。
- DBと写真のバックアップおよび復元試験が成功する。
- 本番導入準備確認で必須項目がすべて合格する。

## 3. 運用開始後の確認

- 毎日：API稼働、同期待ち件数、写真容量。
- 毎週：同期エラー、競合、無効アカウント、監査ログ。
- 毎月：バックアップ復元の抜取確認、TLS証明書期限、写真上限見直し。
- 改訂時：危規則・危告示・IMDG Code・関連資料AI要約の更新日と適用日。
