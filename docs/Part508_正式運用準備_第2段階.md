# Part 508 正式運用準備 第2段階

## 対象

法令情報、危険物の判定基準およびP・IBC・T・SP等のコード情報について、原典照合、承認、改正時の再照合、正式利用可否を一貫して管理するための実装です。

## 照合対象

静的マスターから次の3,328件を照合対象台帳へ登録します。

- 危険物・判定基準：2,725件
- コード：594件
- 法令原典：9件

国連番号の重複を除いた件数は2,248件ですが、品名、等級、項目等が異なる行を個別の照合対象として管理するため、危険物・判定基準は2,725件です。

## 実装内容

1. 原典照合対象を項目単位で管理します。
2. 作成・提出者、原典照合者、承認者を同一人物にできないようにします。
3. 原典照合では、次の8項目をすべて確認しない限り「原典照合済み」にできません。
   - 原典の名称・発行者・版
   - 改正日・適用開始日
   - 条文・別表・ページ
   - 数値・単位・上限値
   - 国連番号・等級・コードの対応
   - 例外・注記・脚注
   - 原文リンク・表示開始位置
   - PC・スマートフォンの整理表示
4. 原典ページ、照合コメント、原典PDFのSHA-256、照合者、照合日時を記録します。
5. 承認時に改訂番号と内容チェックサムを固定した承認証明を発行します。
6. 承認済みデータの内容が更新された場合、承認証明を旧版として識別し、「改正再照合待ち」へ戻します。
7. 誤りや改正確認中の情報は「使用停止」にできます。
8. システム設定で次の表示区分を選択できます。
   - 試作・参考表示：未承認情報を注意表示付きで確認
   - 正式運用：承認済み情報だけを正式判断用として扱う
9. 危険物詳細、関連法令、関連資料、EmS画面に承認状態を表示します。

## 適用手順

1. Part 507適用済みフォルダを複製して保管します。
2. Part 508更新ZIPをフォルダ構成のまま上書きします。
3. `server`フォルダで`npm run migrate`を実行し、`096_part508_regulation_source_verification_approval.sql`を適用します。
4. APIを再起動します。
5. システム管理者でログインし、「関連法令 → 法令原典照合・承認管理」を開きます。
6. 「照合対象台帳を更新」を実行します。CLIでは`npm run regulations:catalog`でも実行できます。
7. 安全環境室の担当者が原典照合へ提出します。
8. 作成者と異なる照合者が原典8項目を確認します。
9. 作成者・照合者と異なる安全環境室長またはシステム管理者が承認します。
10. 全対象の承認と本番環境確認が完了後、システム設定を「正式運用（承認済みのみ）」へ変更します。

## 完了条件

- 照合対象台帳が危険物2,725件、コード594件、法令9件と一致する。
- 原典照合者が作成・提出者と異なる。
- 承認者が作成・提出者および原典照合者と異なる。
- 必須8項目に未確認がある場合は照合済みにできない。
- 承認証明に対象キー、改訂番号、原典参照、内容チェックサム、照合者、承認者、日時が保存される。
- 承認後のマスター変更を検出すると「改正再照合待ち」になる。
- 使用停止した情報は正式利用可と表示されない。
- 正式運用モードでは未承認情報が正式判断用として表示されない。

## 未実施事項

導入先のPostgreSQLへ接続していないため、3,328件の実データ登録、複数利用者による照合・承認、改正再照合、承認証明発行の実環境試験は未実施です。また、この実行環境のChromiumがヘッドレス実行時に正常終了しなかったため、Part 508のスクリーンショットによる目視確認は完了していません。これらはIT室が用意する本番相当環境で確認する必要があります。
