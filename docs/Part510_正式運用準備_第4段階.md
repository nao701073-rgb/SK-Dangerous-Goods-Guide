# Part 510 正式運用準備 第4段階

## 1. 対象

正式運用前の第4段階として、バックアップ、復元、システム全体移行および切戻しの仕組みを整備する。

対象は個別データだけではなく、次のシステム全体とする。

- PostgreSQLデータベース
- 申請番号管理、申請書確認結果、固縛力参考算出結果
- 添付資料、関連写真、監査・訂正・承認履歴
- アプリケーション本体、HTML、CSS、JavaScript
- 危険物、国内法令、コード、包装要件等の全マスター
- システム設定、権限・事業所設定、バージョン情報
- バックアップ・同期・定期処理の定義

平文パスワード、MFA秘密鍵、APIトークン、セッション情報および環境変数ファイルは移行対象外とし、移行先の秘密管理基盤で再設定する。

## 2. 実装した機能

### 2.1 完全バックアップ

DBはPostgreSQLカスタム形式、添付資料はアーカイブ、アプリケーションはファイル一覧・サイズ・SHA-256を含むリリースパッケージとして保存する。バックアップごとに取得日時、版、件数、ファイル数、総容量、検証結果を記録する。

### 2.2 復元前の安全措置

復元処理では、明示的な確認文字列を必須とし、実行前に復元先のバックアップを取得する。通常の復元訓練は一時DB・一時ストレージへ展開し、本番環境を変更しない。

### 2.3 システム全体移行

リリースパッケージを移行先へ展開し、マニフェスト、ファイル数、総容量、SHA-256、JavaScript構文を確認する。差分再送が可能な単位でステージングし、確認後に現在版を示すシンボリックリンクを原子的に切り替える。

### 2.4 切替とロールバック

切替後にヘルスチェックを行い、失敗した場合は直前のリリースへ自動的に戻す。切替・切戻しの実行者、日時、対象版、結果および理由を履歴として保存する。

### 2.5 管理画面

システム管理者向けに「正式運用準備 第4段階」画面を追加し、RPO・RTO、保管期間、遠隔バックアップ、復元訓練、移行訓練、切替履歴を確認・記録できるようにした。安全上、ブラウザ画面からOSコマンドやDB復元を直接実行しない。

## 3. 試験結果

### 3.1 静的検証

28項目を検証し、28項目すべて合格した。DBマイグレーション、バックアップ・復元・移行・切替・切戻しスクリプト、秘密情報除外、復元前バックアップ、隔離復元、原子的切替、失敗時ロールバック、管理APIおよび管理画面を確認した。

### 3.2 システムリリース・移行訓練

実際のPart 510ファイル一式からシステムリリースを作成し、次を確認した。

- 対象ファイル数：1,697
- 合計容量：320,149,852バイト
- JavaScript構文エラー：0件
- 移行訓練結果：合格
- 本番環境の変更：なし

### 3.3 表示試験

実際のHTML、CSS、JavaScriptを用い、PC幅1,365pxおよびスマートフォン幅390pxで管理画面を描画した。両方で横方向のはみ出しおよびJavaScriptエラーがないことを確認した。API応答は試験用データを使用した。

## 4. 未実施事項

導入先のPostgreSQL、永続ストレージ、正式ドメインが未指定のため、次は未実施である。

- 実DBを使用したバックアップ取得
- 一時DBへの実データ復元と件数照合
- 添付ファイルの実ストレージ復元
- 遠隔保管先への転送
- 本番相当環境での切替・切戻し
- RPO・RTOの実測

これらはIT室が用意する隔離された検証環境で実施し、結果を管理画面と復旧訓練記録へ登録する。

## 5. 完了条件

第4段階は、導入先環境で次のすべてを満たした時点で完了とする。

1. 完全バックアップが正常に取得できる。
2. 別環境へDB・添付・システムを復元できる。
3. 件数、ファイル数、チェックサムが一致する。
4. ログイン、権限、検索、法令表示、申請管理、写真、固縛力算出が正常に動作する。
5. 本番切替と直前版への切戻しが所定時間内に完了する。
6. RPO・RTOを満たす。
7. 実施者、確認者、承認者および証跡が記録される。
