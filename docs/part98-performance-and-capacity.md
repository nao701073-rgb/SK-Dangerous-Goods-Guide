# 第98回 性能・容量対策

## 実施目的
危険物データ、法令PDF、ラベル画像、写真データが増加しても、初期表示・検索・再訪問時の応答性能を維持できる構成にする。

## 今回の対応

### 1. 危険物検索の索引キャッシュ
- 各UNデータについて、検索用文字列、国連番号、等級、副次危険性、包装コード、特別規定、EmS、積載・隔離コードを初回参照時に正規化して保持する。
- 検索条件側も1回の検索につき一度だけ正規化する。
- 再検索時に全項目の文字列連結・Unicode正規化・EmS解決を繰り返さない。
- `WeakMap`を利用し、元データの寿命を超えて索引だけが残らないようにした。

### 2. Nginx配信圧縮
- JavaScript、CSS、JSON、XML、SVG、テキストにgzip圧縮を適用した。
- 1KB未満の小規模ファイルは圧縮対象外とし、圧縮処理の過剰負荷を避けた。
- `Vary: Accept-Encoding`を有効化した。

### 3. ブラウザキャッシュ
- JS・CSS・画像・フォントは7日間キャッシュし、再検証猶予を付与した。
- 法令PDFは1日間キャッシュした。
- HTMLは常に再検証し、更新後も古い画面だけが残る状態を防止した。
- Nginxのopen file cacheを有効化し、同一静的ファイルへの反復アクセス時のファイルシステム負荷を抑えた。

### 4. PNGの可逆再圧縮
- ラベル画像および表示ガイド画像の画素寸法・内容を変えず、メタデータ削除とPNG圧縮設定の最適化を実施した。
- 約95KBを削減した。画像品質の劣化を伴う非可逆圧縮は行っていない。

## 容量上の確認事項
ZIP展開時の主要容量は、法令原本PDF群、`data/un-data.js`、高解像度ラベル画像群が中心である。法令PDFは原本性とページ参照機能を優先し、今回は内容変更や分割を行っていない。

## 将来の拡張方針
- UNデータが大幅に増加する場合は、分類・国連番号帯ごとの分割読込またはAPI検索へ移行する。
- 申請番号・写真一覧が数千件規模を常態化する場合は、APIのカーソル方式ページングを導入する。
- 写真容量が増加する場合は、サムネイル自動生成、原本と表示用画像の分離、保存期間ルールの運用を追加する。
- 法令PDFを外部ストレージへ移す場合も、版番号・ハッシュ・ページ参照先を固定して原本性を担保する。
