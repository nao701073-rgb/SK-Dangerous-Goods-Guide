# Part 532 第28～第30段階
## データ性能・添付資料・横断整合性管理

## 1. 目的

申請番号管理、申請書確認、申請書・写真・添付資料、共通案件情報、固縛力参考算出、危険物検索を安定して運用するため、次の三分野を一つの管理画面で確認します。

1. DB・検索性能と索引品質
2. 申請書・写真・添付資料の参照健全性
3. 申請番号・共通案件情報・固縛力参考算出の横断データ整合性

管理画面は `pages/data-integrity-performance-admin.html` です。

## 2. 第28段階：DB・検索性能と索引品質

環境別に次の実測値を登録します。

- DBクエリP95応答時間
- 検索P95応答時間
- 失敗クエリ率
- キャッシュヒット率
- DB接続使用率
- インデックス膨張率
- 検索結果0件率
- 危険物索引件数
- 固有国連番号索引件数
- 証跡参照番号とSHA-256

危険物索引件数は2,725件、固有国連番号は2,248件との一致を確認します。不一致は重大状態として扱います。

## 3. 第29段階：申請書・写真・添付資料の参照健全性

ファイル本文や個人情報を台帳へ複製せず、件数と証跡だけを登録します。

- 総ファイル数
- 申請・案件へ正しく関連付いたファイル数
- 孤立ファイル数
- 欠落ファイル数
- SHA-256不一致数
- マルウェアスキャン待ち・不合格数
- メタデータ不一致数
- 隔離中ファイル数

欠落、SHA-256不一致、スキャン不合格、隔離中ファイルがある場合は重大状態です。

## 4. 第30段階：横断データ整合性

次の関係を一括確認します。

- 申請番号の重複
- `applications.case_data` の共通案件スキーマ
- 申請番号管理と固縛力参考算出の案件参照
- 申請書・添付資料・写真の参照
- 申請訂正履歴の連番
- 事業所範囲
- 利用者参照

Part 529で追加した共通案件情報と双方向連携を、単なる画面機能ではなく運用データ全体の整合性対象として扱います。

## 5. 是正課題

重大度別の期限は次のとおりです。

| 重大度 | 期限 |
|---|---:|
| 重大 | 1日 |
| 高 | 7日 |
| 中 | 30日 |
| 低 | 90日 |

責任者、是正実施者、結果検証者を分離します。重大・高課題が未解決の場合、データ保証レビューを承認できません。

## 6. レビューと承認

レビューは次の三者を分離します。

- 作成・提出者
- 確認者
- 最終承認者

提出時に、三種類の測定ID、未解決課題ID、阻害要因をスナップショット化し、SHA-256を固定します。承認時に改変されている場合は拒否します。

## 7. 承認ゲート

次の条件を満たす必要があります。

- 本番環境の三種類の測定がすべて存在する
- 各測定が24時間以内である
- 各測定が重大状態ではない
- 未解決の重大・高課題がない
- 中・低課題に期限超過がない

## 8. 権限

閲覧対象：

- システム管理者
- 安全環境室長
- 安全環境室職員
- 改正検証者

登録・是正・承認操作はシステム管理者に限定しています。

## 9. 本番適用

バックアップ取得後、次のマイグレーションを適用します。

```text
server/sql/115_part532_data_integrity_performance_governance.sql
```

PostgreSQL、実ファイルストレージ、実検索ログを使用した測定は本番相当環境で実施してください。検索語や申請書本文などの機密情報を証跡台帳へ登録しないでください。
