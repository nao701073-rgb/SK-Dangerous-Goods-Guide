# Part 574 更新仕様

## 1. 申請書確認：確認完了ガイド
Part 568〜573で追加した要確認ナビ、登録準備表示、前回差分、全差分ナビを横断し、登録前の確認状態を1か所にまとめる。

### 必須確認として表示
- 危険物明細の未確認・修正必須件数
- 原本照合者の入力状態

### 再確認補助として表示
- 前回登録内容との差分チェック進捗
- 全体確認事項・注意事項

「差分チェック済み」はPart 573と同じく画面補助のみであり、`reviewEvidence`、確認済み判定、登録可否には使用しない。「未完了へ移動」は既存入力・既存ボタンへフォーカスするだけで、自動確認や自動登録は行わない。

## 2. 申請番号管理：要確認案件キュー
アクセス可能な申請案件を横断し、次の条件に該当する案件を優先表示する。

1. 申請書確認記録がない
2. 申請書確認に未解決項目がある
3. 使用予定のMSL取付点に未確認がある

キューは表示補助であり、案件データを書き換えない。案件カードを押すと、既存の申請番号選択欄をその案件へ切り替え、Part 566〜573の案件操作・確認表示をそのまま利用する。

## 3. 固縛力参考算出：最終算出根拠メモ
最後に「この条件で算出する」を正常に実行した時点で、次の画面情報を表示用スナップショットとして保持する。

- 申請案件
- 輸送条件・CTU
- 貨物質量・接触面・摩擦係数
- 固縛区分・方法・固縛材・方向・本数
- 固縛材強度と強度根拠
- 貨物側MSL、CTU側MSL
- Part 567の採用MSL表示
- Part 570のMSL根拠確認状態
- 支保・当て材条件（該当時）
- 算出結果表示

算出後に条件が変更された場合は、Part 573の変更追跡と連動して「最後に算出した時点の根拠」であることを明示する。再算出後にスナップショットを更新する。

「根拠要点をコピー」は利用者の明示操作時のみクリップボードへ送る。計算結果や申請案件への保存は、従来の登録処理を使用する。

## 4. 互換性
DBマイグレーションなし。Part 573までの既存JS/CSS、判定ロジック、計算ロジック、保存データ形式を維持する。
