# Part 100 法令改正差分・原文照合・公開前検査

## 目的
法令PDFを追加する運用を、危規則、危告示、IMDG Code、その他国内・国際法令に共通適用できるようにする。改正版PDFと構造化データを一組として登録し、比較元版との差分を確認してから承認・公開する。

## 追加内容
- 更新種別（改正、新版、訂正、翻訳・参考資料更新）
- 対象データキーとレコード識別キーの明示
- 新旧JSONの追加・変更・削除件数プレビュー
- 削除データの抽出漏れ確認を促す警告
- 原文照合予定項目のチェックリスト
- 更新マニフェスト schemaVersion 1.1
- 共通データセット包み形式（records配列）
- サーバー用差分生成スクリプト
- 原文頁参照、削除理由、差分ハッシュを保存するSQL拡張

## 推奨ファイル単位
1回の改正につき、次を同じ改正IDで管理する。

1. 公式PDF原本
2. 更新マニフェストJSON
3. 対象ごとの構造化データJSONまたはCSV
4. 自動生成した差分JSON
5. 原文照合記録
6. 承認・公開記録

## データセット形式
JSONは配列そのもの、または以下の包み形式を利用できる。

```json
{
  "schemaVersion": "1.0",
  "regulationId": "domestic-dangerous-goods-notification",
  "editionLabel": "令和○年改正",
  "targetKey": "UN_DATA",
  "recordKey": "unNumber",
  "records": []
}
```

## 差分検査
ブラウザ試作画面では比較元JSONと新JSONを指定して差分を表示する。サーバーでは次を実行できる。

```bash
npm run diff:regulation -- baseline.json next.json unNumber
```

終了コード1は削除レコードがあることを示す。削除自体をエラーとは断定せず、原文上の削除か抽出漏れかを確認する。

## 公開条件
- PDF SHA-256登録済み
- 構造化データのスキーマ検証合格
- 比較元版が確定
- 追加・変更・削除差分を確認済み
- 削除がある場合は理由を記録
- PDF該当頁との照合記録あり
- 安全環境室管理者の承認あり
- 施行日と公開日時が整合
