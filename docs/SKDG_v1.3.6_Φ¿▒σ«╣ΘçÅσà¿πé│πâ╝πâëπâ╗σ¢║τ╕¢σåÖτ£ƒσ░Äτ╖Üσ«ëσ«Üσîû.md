# SKDG v1.3.6 許容容量全コード・固縛写真導線安定化

## 1. 目的
v1.3.5で復旧した申請書自動確認をP200の代表例だけに限定せず、登録済み危険物全体で使用される包装・輸送コード体系へ広げて再確認する。同時に、固縛力参考算出の開始導線を「申請書・航路 → 写真撮影／アップロード」の順に固定し、読み込み後に画面構成が入れ替わらないようにする。

## 2. 申請書確認：許容容量・許容質量
- P001 / P002：構造化表を使用し、容器コード・容器等級に応じて数値を表示する。
- P200：容器種類・許容容量・許可条件を既存P200参照ロジックで表示する。
- その他Pコード：原文から安全に確定できる候補のみ表示し、個別条件があるものは原文照合へ誘導する。
- IBC：IBCコード、容器コード、容器等級等から最大内容積候補を表示する。
- T / TP：ポータブルタンクの試験圧力・外板・安全装置・底部開口等を表示し、個別条件コードは原文照合とする。
- LP / BK：一律数値を作らず、適用される原文参照先を表示する。
- 旧呼出名 `resolveAllowance()` にも互換対応し、キャッシュが混在した環境で関数未定義にならないようにする。
- P112は危告示PDF 289～290頁を原文参照先として補完する。

## 3. 全登録データの参照カバレッジ
登録済み危険物2,725行について使用コードを抽出して確認した。
- Pコード：84種類、参照先欠落 0
- IBCコード：12種類、参照先欠落 0
- Tコード：19種類、参照先欠落 0
- LPコード：13種類、参照先欠落 0
- BKコード：2種類、参照先欠落 0

数値を自動確定できないコードを無理に数値化せず、「原文照合が必要」という有効な確認結果として扱う。

## 4. 固縛力参考算出
ページ上部のDOM順序を最初から次の順に固定する。
1. 申請書・航路から入力する
2. 写真を撮影・アップロードする
3. 写真AI候補を確認する
4. 登録済み案件から入力する（必要な場合）
5. 不足項目を確認して参考算出

写真入力は以下を維持する。
- スマートフォン等のカメラ撮影
- 既存写真の複数アップロード
- 写真AI候補の表示
- 固縛材と支保・あて材の候補を別々に整理
- 材質、本数、接触状態、MSL表示、角度等を候補として提示
- 検査員が採用した候補だけ入力へ反映
- MSLや安全性は写真だけで自動確定しない

## 5. 画面安定性
- ①申請書／②写真の位置変更をロード後JavaScriptで行わない。
- v1.3.1の旧配置変更スクリプトは読み込まない。
- 自動スクロールは既定OFFを維持する。
- 写真候補の更新処理は候補領域内に限定し、ページ上部カードを動かさない。

## 6. 計算ロジック
固縛力の既存計算式は変更しない。申請書・写真は入力補助として扱い、「この条件で算出する」の明示操作で参考算出する。

## 7. DB
DBマイグレーションなし。
