# SKDG v1.3.76 CTU Code／CSS Code 抵抗力再監査

## 1. 修正目的
v1.3.75では、CTU種類を「汎用貨物コンテナ」にしただけでCTU境界抵抗が大きく見える経路が残っていた。とくに旧版由来の `P=28 t` と前後0.4P／側面0.6Pが、貨物の密着・荷重伝達条件を個別確認していない案件へ事実上入り得ることが問題だった。

v1.3.76では、抵抗力を「数値が出ること」より「その抵抗が実際に成立する条件を確認できていること」を優先して評価する。

## 2. CTU Code 再照合結果
- 第5章の道路・鉄道・海上A/B/Cの `cx, cy, cz` は現行プリセット値と整合している。
- 汎用貨物コンテナの境界強度候補は、側壁0.6P、前壁・扉端0.4Pを維持する。
- P はCTUの maximum payload であり、固定28 tを使わない。CSC安全承認板等で確認した実値だけを入力する。
- 境界抵抗は、貨物が境界へ密着し、隙間・衝撃荷重・局部過負荷を避け、荷重を境界へ伝達できることを個別確認した場合だけ算入する。
- 摩擦抵抗は `μ × cz × m × g`。直接固縛を含む方向では静止摩擦係数の75%を使用する。
- トップオーバーは**垂直掛けの参考算出に限り** `1.8 × STF × μ` を1本当たりの追加抵抗の基準として扱う。斜め掛け等は詳細な荷重方向を別途確認する。
- 直接固縛は器具MSL、貨物側取付部MSL、CTU側固縛点MSLの最小値を採用し、鉛直角・水平角の対象方向成分を使用する。
- 支保・当て材と直接固縛は荷重変形特性が異なり得るため、簡易の併用確認チェックだけでは相互に加算しない。承認された荷重分担・剛性条件を詳細設定で確認した場合だけ加算モードを使う。
- CTU境界抵抗と支保／直接固縛について独立した荷重経路が確認できない通常の簡易算出では、保守的に単純加算しない。詳細設定で承認された方法・荷重経路を確認した場合のみ加算モードを使える。


## 2.1 Step 4 摩擦係数の連動不具合も修正
再監査中、Step 4に表示される参考摩擦係数と、Step 6が実際に使用する非表示の `quickMu` が連動していない経路を発見した。例えば「木・木製パレット／金属床・鋼板／乾燥・清浄」で画面が `μ=0.20` と表示していても、旧実装では計算値が `μ=0.30` のまま残る場合があった。

v1.3.76では旧 `v1368-ctu-canonical-runtime.js` 全体を復活させず、摩擦連動だけを専用モジュール `v1376-ctu-friction-sync.js` として分離した。これにより旧DOM並べ替え処理を再導入せず、Step 4表示値・簡易算出値・詳細設定値を一致させる。

Step 4の材質区分は原典表より広いため、自動値は「表の厳密な一点値」ではなく保守側参考候補として扱う。初期の「木・木製パレット／金属床・鋼板」は `μ=0.20` とし、直接固縛時の計算摩擦係数はその75%で `μ=0.150` となる。正確な接触材組合せ、試験値、認証値がある場合は詳細設定で上書きできる。

- 未掲載・未検証の組合せは、自動値を0.30より大きくしない。
- 霜・氷・雪は0.20以下。
- 油・グリース等は0.10。
- 旧案件で接触材の組合せが保存されていない場合は、保存済みμだけを復元し、Step 4に「旧案件の保存値・接触材要再確認」と表示する。

また、詳細設定で直接固縛とトップオーバーが同一評価方向に混在する場合は、直接固縛を含む配置として摩擦依存成分に75%摩擦係数を適用する。トップオーバー単独では静止摩擦係数を使用する。簡易入力のトップオーバー欄はSTF入力であり、STFをMSLとして誤登録しないよう内部項目を分離した。

## 3. v1.3.76 の抵抗合成
### 通常（保守的評価）
`摩擦 + トップオーバー + max(CTU境界, 支保, 直接固縛)`

Step 5の併用確認チェックは、作用方向・接触状態を確認した記録であり、算術加算の許可には使用しない。特に木材支保等と直接ウェブラッシングを滑り止めとして並列使用する場合、CTU Code Annex 7 4.1.6の考え方に従い、保守的簡易算出では強い方のみを採用する。

### 詳細設定で承認根拠を確認した場合
`摩擦 + トップオーバー + CTU境界 + 支保 + 直接固縛`

この加算モードは、荷重経路・剛性・施工状態・承認資料が独立に成立することを確認した場合だけ使用する。単なる現場確認チェックでは自動的にこのモードへ移行しない。

## 4. 全方向入力の扱い
「全方向」は誤解を避けるため「各評価方向に同じ有効本数を適用（要確認）」へ改称した。写真で確認できる物理的な総本数を、前後左右すべてへ自動的に重複計上する意味ではない。各方向に実際に有効な本数・取付方向・水平角を確認する。

## 5. CSS Code Annex 13 再監査
Part478で原典照合した実装を基準に再確認したところ、2020年改正内容に対して**2点の保守側ではあるが原式と一致しない処理**を発見したため、v1.3.76で修正した。

- 経験に基づく方法：左舷・右舷各側のMSL合計と貨物重量を比較する処理は維持。
- 先進の計算方法：CS = MSL / 1.5、表6の係数 `f = μ sin α + cos α` を維持。
- **縦方向成分の上限**：旧実装は `0.5 × f × CS` としていたが、改正Annex 13の「横方向固縛の縦方向成分は0.5CSを超えない」という上限に合わせ、`min(f, 0.5) × CS` に修正。
- **縦方向摩擦の縦力補正**：旧実装は `μ × (m×g − Fz)` としていたが、改正Annex 13の縦力補正係数 `fz` を導入し、`μ × (m×g − fz×Fz)` に修正。`μ=0.0/0.1/0.2/0.3/0.4/0.6` に対する `fz=0.20/0.50/0.70/0.80/0.85/0.90` を実装し、中間値は線形補間する。
- 代替の方法：CS = MSL / 1.35、`fy = cosα cosβ + μ sinα`、`fx = cosα sinβ + μ sinα` の鉛直角・水平角処理を維持し、縦方向摩擦には同じ `fz` 補正を適用。
- 表2の基礎加速度、表3の船長・速力補正、表4のB/GM補正、表5の摩擦係数は変更なし。
- 表1による名目破断力→MSL換算、器具／貨物側／船側の最小MSL採用は変更なし。
- 異なる弾性の固縛の保守的除外、トップオーバーをAnnex 13平衡計算へ算入しない処理は維持。

Part478との差分検査では、12項目中11項目は完全一致し、`lashingForDirectionCss` だけが上記の縦方向0.5CS上限修正のため意図的に変更された。さらに `calc()` 内の縦方向摩擦へ `fz` 補正を追加した。CSS Codeモードは引き続き参考算出であり、承認済みCargo Securing Manual、船固有の条件、主管庁・船級の承認を優先する。

## 6. 保存案件の安全な復元
- 旧版の `uniformWallLoad=true` だけではCTU境界抵抗を自動復元しない。
- `wallLoadTransferConfirmed=true` と対応する確認済みPがそろう場合だけ境界算入状態を復元する。
- 「すべて確認しました」ボタンはCTU境界算入を自動ONにしない。
- 詳細設定の別ウィンドウで計算条件を変更した場合は、元画面の算出結果を「再算出必要」として無効化し、古い抵抗値を最新値として扱わない。

## 7. 表示回帰
PC・スマートフォンで、①〜⑥の順序、追跡表示、Step 4のμ連動、Step 5、Step 6、算出内訳、詳細設定別ウィンドウ、「すべて確認しました」、横スクロール、JavaScript本文露出の有無を確認する。

同一ブラウザハーネスでv1.3.75と比較し、意図した文言・抵抗内訳以外にレイアウト崩れがないことも確認対象とする。
