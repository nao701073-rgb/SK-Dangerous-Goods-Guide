# Part 569 確認理由・写真/MSL連携改善

## 1. 申請書確認
- `.part562-reasons` の理由チップはデータ自体を削除せず、通常表示のみ2件へ圧縮する。
- 3件以上は「ほかN件」で展開可能。
- Part 565の `reasonList()` は従来どおり全 `span` を取得するため、登録時の `reviewEvidence.humanConfirmed[].reasons` と `reasonGroups` は全理由を保持する。
- Part 568の要確認ナビと組み合わせ、現在の要確認行のUN番号と主要理由を上部へ表示する。

## 2. 申請番号管理
- 選択中案件に対する簡易メモ保存後、その案件を維持したまま写真入力を起動できる。
- 既存の `quickSaveMemo`、`quickAddPhoto`、`photoFile` を再利用し、保存形式や写真管理ロジックは変更しない。
- 写真だけ追加する場合も、既存 `quickAddPhoto` で `photoApplication` を設定してからファイル選択を開く。

## 3. 固縛力参考算出
- 既存の写真確認欄（刻印・表示、確認MSL kN）を残したまま、その直下へ単位換算補助を追加する。
- 対応単位：kN / daN / N / kgf / tf。換算係数は既存取付点台帳の考え方と一致させる。
- 「刻印文字から候補」はOCRではなく、利用者が入力した刻印文字列から `数値＋単位` を抽出する入力補助。自動確定はしない。
- 「換算してMSLへ反映」は換算後のkNを既存 `quick*PhotoValue` へ入れて、既存の写真根拠反映処理を実行する。
- 「反映＋案件写真登録」は既存のMSL反映と案件写真保存ボタンを順に実行する。
- 固縛力計算式、最小MSL採用ロジック、併用計算には変更を加えない。

## 4. データ互換性
- DBマイグレーションなし。
- 新規永続フィールドなし。
- Part 568以前の案件をそのまま開ける。
