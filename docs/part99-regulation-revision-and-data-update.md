# Part 99 法令改正・データ更新管理

## 目的
危規則、危告示、IMDG Code、その他の国内・国際法令について、規則改正のたびに原本PDFと対応データを追加し、履歴を失わず安全にデータベースを更新する。

## 基本原則
1. PDF原本を更新の根拠資料として保存する。
2. PDF追加のみでは本番データを自動変更しない。
3. OCR・AI抽出は入力補助として扱い、原文照合を必須とする。
4. 構造化データの検証、差分確認、安全環境室の承認後に公開する。
5. 旧版、現行版、将来施行版を同時に保持し、施行日で適用版を判定する。
6. SHA-256、登録者、照合者、承認者、公開日時を監査記録として残す。
7. 公開後に誤りが判明した場合は、旧版を削除せずロールバック公開する。

## 対象例
- 危険物船舶運送及び貯蔵規則（危規則）
- 船舶による危険物の運送基準等に関する告示（危告示）
- IMDG Code
- 高圧ガス保安法および関係省令・告示
- 放射性物質等の運送関係法令
- CTU Code、MARPOL、CSCその他の国際条約・コード

## 更新フロー
1. **原本登録**：法令ID、版、公布日、施行日、言語、発行元、PDFを登録する。
2. **真正性確認**：PDFのSHA-256を計算し、同一ファイルや改ざんを検知する。
3. **データ作成**：法令別のJSON/CSVスキーマに従って条文、別表、UNデータ、コード対照等を作成する。
4. **自動検証**：必須項目、型、重複、参照整合性、件数急変、削除件数を検査する。
5. **差分確認**：現行版との追加・変更・削除を項目単位で表示する。
6. **原文照合**：担当者がPDF該当頁と構造化データを照合する。
7. **承認**：安全環境室管理者が変更セットを承認する。
8. **公開**：即時または施行日に公開し、検索索引とキャッシュを再生成する。
9. **監査・復元**：公開版、旧版、変更理由、承認者を保持し、ロールバック可能とする。

## データ設計
- `regulation_sources`: PDF原本と版情報
- `regulation_datasets`: PDFに対応するJSON/CSV
- `regulation_change_sets`: 現行版との差分と審査状態
- `regulation_publications`: 公開履歴とロールバック関係
- `data/regulation-revision-registry.js`: オフライン表示用の版台帳
