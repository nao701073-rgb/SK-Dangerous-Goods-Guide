# Part 536 登録後再確認画面・全危険物許容容量／許容質量表示見直し

## 1. 目的

Part 536では、申請番号管理へ登録した案件を後から確認するときの見づらさを解消する。

対象は次の3画面である。

- 申請番号管理
- 申請書取込・確認
- 固縛力参考算出

既存の申請書取込機能、事前チェック、入力項目、固縛力参考算出の計算式・係数・判定・保存処理は変更しない。

## 2. 画面統合

ホーム画面と共通メニューでは、従来の「申請書確認」と「申請書・依頼書取込」を重複表示せず、入口を **「申請書取込・確認」** に統一した。

処理の流れは次のとおりである。

1. Excel・CSVを取り込む
2. 読取内容を確認・修正する
3. 事前チェックを実行する
4. 申請番号管理へ登録・引き継ぐ

許容容量・許容質量の詳細照合画面は削除せず、申請書取込・確認画面から必要時に開く補助機能として維持する。

## 3. 登録後の再確認画面

### 3.1 申請番号管理

危険物明細を横長表ではなく、1危険物ごとのカードで表示する。

- 国連番号・品名
- 等級・容器等級
- 容器コード・包装要件
- 個数
- 1容器当たりN/W・G/W
- 申請総N/W・G/W
- 許容容量・許容質量
- 許可・確認事項
- 原文リンク

### 3.2 申請書取込・確認

取込・編集用の項目および処理は維持し、危険物明細をカード状に並べる。登録した確認結果を開いた場合も同じカード形式で表示する。

### 3.3 固縛力参考算出

計算機能には変更を加えず、申請番号管理から読み込んだ案件の概要と危険物明細を、計算入力欄とは別の読取専用カードで表示する。

## 4. 許容容量・許容質量の全件見直し

危険物マスター2,725行、固有国連番号2,248件を対象に、小型容器包装要件と原文参照を再検査した。

| 区分 | 件数 | 表示・確認方法 |
|---|---:|---|
| P001・P002構造化照合 | 1,598 | 容器コード・容器等級に応じて表から照合 |
| P200 | 170 | 容器種類、充てん条件、最大圧力、許可内容を原文で確認 |
| その他のPコード | 915 | 危告示原文の該当ページへ接続し、申請容器の該当行で確定 |
| 小型容器包装要件なし | 42 | タンク、IBC、大型容器、放射性輸送物等の個別条件を明示 |
| **合計** | **2,725** | **未対応0件** |

使用されているPコード84種類は、すべて法令マスターの原文とページ情報へ接続している。

## 5. 判定上の注意

Part 536は、すべての危険物について確認経路を用意するものであり、申請情報が不足している場合まで一律の数値を自動確定するものではない。

- P001・P002は構造化表による照合を行う。
- P200は原文、容器、充てん条件および許可内容を確認する。
- その他のPコードは原文該当行を表示し、容器種類、物品形態、追加規定から確定する。
- 組合せ容器、少量危険物、現物表示が必要なものは現場確認を維持する。

## 6. レスポンシブ表示

- PCでは情報を2～4列に整理する。
- スマートフォンでは1列表示へ切り替える。
- 危険物明細の横スクロールを廃止する。
- 長い品名・許可事項・原文案内は折り返す。
- ボタン、入力欄、色、余白は現在公開中画面の書式へ合わせる。

## 7. 機能維持の確認

Part 535とSHA-256比較を行い、次の既存実装が同一であることを確認した。

- 申請書取込・事前チェックのブラウザポリシー
- 申請書取込のサーバーポリシー
- 共通案件情報の正規化・保存処理
- 申請番号管理のストレージ処理
- 固縛力参考算出の `calc`、係数設定、壁強度設定、入力同期処理

## 8. 本番相当環境での確認事項

- 実際のExcel申請書による取込
- 登録済み案件を再度開いた場合の表示
- PC・スマートフォン実端末での折返し・スクロール
- 原文PDFの該当ページ表示
- 権限別の申請番号管理・固縛力参考算出操作
- オフライン状態と再同期後の表示
