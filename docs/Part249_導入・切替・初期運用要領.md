# Part 249 導入・切替・初期運用要領

## 1. 目的
Part 248までに整備した配置準備を、実際の導入、切替、ロールバック準備、運用開始後の初期点検へ接続する。

## 2. 実施順序
1. 配置前検査を実行する。
2. PostgreSQLを作成し、SQLを番号順に適用する。
3. 写真保存領域とアクセス権を設定する。
4. Node.js APIを配置し、HTTPS、CORS、ヘルスチェックを確認する。
5. 画面を配置し、API URLを設定する。
6. 招待、MFA、パスワード再設定メールを実送信する。
7. 初期利用者CSVを事前検証してから登録する。
8. 役割別の閲覧・登録・編集・削除制御を確認する。
9. 切替直前バックアップとロールバック資材を保存する。
10. 主要機能の通し試験と性能試験を行う。
11. 利用者周知と問い合わせ窓口を確認して切り替える。

## 3. 配置前検査
`server`フォルダで以下を実行する。

```powershell
npm run deployment:preflight
npm run verify:integrated
npm run permissions:audit
npm run data:release-check
```

## 4. 切替判定
実行フェーズが完了し、重大な障害がなく、バックアップと復元手順が確認できた場合に限り「切替可」とする。

## 5. ロールバック
切替後に認証不能、重大な権限不整合、データ破損、写真保存不能などが発生した場合は、新規登録を停止し、前版の画面・API・データベースへ戻す。発生時刻、影響範囲、判断者、復旧内容を記録する。

## 6. 開始後点検
開始後1日、7日、30日に、ログイン、権限、メール、同期、バックアップ、性能、問い合わせ、法令更新手順を確認する。

## 7. 利用方針
本システムの利用は任意です。利用頻度の低さや未使用自体を警告・評価対象としない。
