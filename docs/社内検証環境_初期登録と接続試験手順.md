# 社内検証環境 初期登録・接続試験手順

## 1. 初期構築

1. `server/.env.example`を`server/.env`へコピーする。
2. PostgreSQL、JWT秘密鍵、管理者メール、初期パスワード、TLS関連の値を設定する。
3. `server/nginx/certs`へ社内検証用証明書と秘密鍵を配置する。
4. `docker compose build`を実行する。
5. `docker compose up -d db`を実行する。
6. `docker compose run --rm api npm run migrate`を実行する。
7. `docker compose run --rm api npm run seed`を実行する。
8. 必要に応じて`docker compose run --rm api npm run seed:validation`を実行する。
9. `docker compose up -d`で全サービスを起動する。

## 2. 検証用初期データ

`npm run seed:validation`では、第一ブロック4事業所に対応した検証利用者と、各事業所1件の申請番号サンプルを登録します。

- 安全環境室 検証管理者
- 首都圏サーベイセンター 検証管理者
- 川崎事業所 検証管理者
- 横浜事業所 検証利用者
- 横浜大黒事業所 検証利用者

初期パスワードは環境変数`VALIDATION_INITIAL_PASSWORD`から読み込み、全利用者に初回変更を要求します。本番環境では検証アカウントを無効化または削除してください。

## 3. 管理画面

1. 設定画面で社内API接続先を登録する。
2. 安全環境室管理者でオンラインログインする。
3. 設定画面の「社内検証管理」を開く。
4. 基本接続試験を実行する。
5. 必要な利用者・事業所を追加する。
6. 「新しい検証を開始」からチェックシートを作成する。
7. 各項目の実際の結果、合否、備考を登録する。
8. 最終的に「合格」「要改善」「中止」のいずれかで完了する。

## 4. 必須検証項目

- APIヘルスチェック
- 安全環境室・事業所利用者のログイン
- 事業所閲覧範囲と安全環境室の横断閲覧
- 申請番号の登録・他端末閲覧
- 同時更新競合
- 写真登録と容量・枚数上限
- オフライン後の同期と二重送信防止
- 監査ログ
- バックアップ・復元
- TLS証明書期限確認

## 5. 本番移行条件

- 不合格項目が解消されていること
- 管理者・一般利用者の権限が承認されていること
- 本番DNS・TLS証明書が設定されていること
- 初回バックアップと復元試験に合格していること
- 検証用アカウント・サンプル申請番号の処置が決定していること
